## Round 8 — a gate that was asserting a fact about the operator's desk

`toolkit_runtime_not_target_capability` went red during a full-suite run with no code change
behind it:

```
not ok 9 - AT-009: Capability detection and explicit authentication/billing modes
toolkit_runtime_not_target_capability
false !== true
```

The assertion required `adb devices` to list nothing — it was written on a machine with no
phone attached, and read that absence as proof that "the tool answered" is not "the target is
present". An Android device was plugged into this machine, `adb` reported it, the target was
correctly detected as available, and the gate failed with nothing wrong.

The rule is about the toolkit, so it now runs against probes that answer identically on every
machine: one that exits zero and reports nothing attached, one that exits zero and reports the
thing present, and one whose tool is not installed at all. The live `xcrun simctl` and `adb`
probes stay in the report as observations of this machine — what they find is a fact about the
desk, and it is recorded as one rather than asserted.
