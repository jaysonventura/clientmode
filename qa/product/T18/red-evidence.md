## Round 2 — the operator surface, added after the first client-readiness pass

`commands_match_operations_contract` used to check only that the declared surface matched the
operations contract. Nothing ran the commands. Seven of the thirteen — `pause`, `resume`,
`cancel`, `verify`, `export-evidence`, `rollback`, `upgrade` — were declared and had no terminal
entry point at all.

The gate now invokes every command for real, in its own state home, with a well-formed request
naming something that does not exist. Three things are asserted:

- none exits `missing_capability` from the dispatcher, which is what an unwired command returns;
- every exit code is one the contract defines;
- none exits `internal` — a crash is not an answer to "no such candidate".

It also opens one project from six processes at once, and a fresh state directory from eight
processes released at the same wall-clock instant.

### Three real bugs this round found

1. **Seven commands were declared and unrunnable.** Now wired to the modules the gates already
   exercise, each returning a contract exit code.
2. **Two terminals in one project crashed one of them.** The state-directory lock was taken on
   every open, not just by the process that owns the run loop. Six concurrent `cm status` calls
   produced one crash; now all six answer.
3. **`PRAGMA busy_timeout` was set after `PRAGMA journal_mode = WAL`.** The statement that waits
   longest is the journal switch, and it ran before the timeout that would have let it wait. Eight
   processes opening a fresh project at one instant: **all eight failed**. All eight now succeed.
   The barrier is what exposed it — spawning processes and hoping they overlap is not a race test,
   because startup latency staggers them and the first has finished migrating before the second
   begins.

### A flaky gate, caught and fixed

The first version ran all fourteen invocations against one shared state home. `rollback` then
sometimes found a snapshot that the parallel `upgrade` had just taken, and answered 0 instead of
2. Each command now gets its own home: a gate whose answer changes between runs is measuring the
scheduler, not the code.
